この段階では作っていません。デザイン（下の図）を確認してもらってから作ります。

1. 要件

機能できること入口
①中まで見つかる検索Mac の検索（Spotlight・Finder の検索窓）で、圧縮ファイルの中のファイル名を打つと、その圧縮ファイルが見つかる。解凍は不要。入れるだけ（設定なし）
②2つを比べる圧縮ファイル同士、または圧縮ファイルとフォルダを比べて、「増えた・消えた・変わった・同じ」を一覧で見せる。差分だけを取り出せる。メニュー「ファイル → 2つを比べる…」(⌘⇧D)、中身の窓の「その他 → ほかと比べる…」、2つまとめて Dock アイコンにドロップ
③選んだものだけ送る中身の窓で選んだファイルだけを新しい zip にして、AirDrop・メール・メッセージなどへ送る。保存するだけも選べる。右クリック／「その他 → 選んだものを送る…」
④お片付け選んだフォルダ（最初はダウンロード）から、解凍済みの圧縮ファイルと同じものが2つある圧縮ファイルを見つけ、選んでゴミ箱へ入れる（ゴミ箱から戻せる）。メニュー「ファイル → お片付け…」

「取り出したあと元の圧縮ファイルをゴミ箱へ」はすでに設定にあるので、④は「あとからまとめて片付ける」機能にします。

2. 技術選定

アプリ本体は今のまま（Swift＋SwiftUI、Xcode 26.6、Swift 6.3）。新しい外部ライブラリは使いません。②③④は今ある部品（目次の読み取り・取り出し・圧縮）の組み合わせで作れます。比べる必要があるのは①の作り方だけです。

①の作り方の比較

A. 検索用の取り込み部品（.mdimporter、C言語）B. 新しい取り込み部品（CSImportExtension）C. アプリが自分で登録（CSSearchableIndex）
動作の軽さ◎ Mac の検索が必要なときだけ呼ぶ◎△ アプリがフォルダを見張り続ける
配布サイズ◎ 数十 KB◎◎
作りやすさ○ 古い形式だが単純—△ 見張る場所の許可・更新が面倒
対応OS◎ macOS 14〜26 すべて× Mac では動かないと公式に明記○
将来性○ Mac ではこれが今も正式な方法×○
AIでの書きやすさ○—○
見つかるものどこに置いた圧縮ファイルでも—見張っている場所だけ

おすすめ：A。Apple の資料に「Mac で独自のファイルを検索に載せるには、取り込み部品（Spotlight importer plugin）を作る」とあり、B は「Mac では機能しない」と書かれているためです。中身の読み取りには Mac に最初から入っている libarchive を使います（Quick Look と同じ方法で、もう実績があります）。

根拠：CSImportExtension（Apple）／Spotlight Importer Programming Guide（Apple）／Apple 開発者フォーラム（Mac は .mdimporter、と DTS 回答）

わかっている制限（事実）：検索で出てくるのは圧縮ファイルそのものです。中の1ファイルずつを検索結果に並べる仕組みは、Mac の検索にはありません（上のフォーラムの Apple 回答）。出てきた圧縮ファイルを開くと、ZipPeek の中身の窓が開きます。
Apple 以外のツールが zip に同じ部品を入れている場合、どちらが使われるかは Mac が決めます（未確認）。

4. 部品の分け方

ZipPeekCore（アプリと切り離した中身の処理。Linux でもテストする）
  ArchiveDiff       … 2つの一覧を比べて、増えた・消えた・変わった・同じに分ける
  FolderListing     … フォルダを「圧縮ファイルの目次」と同じ形で読む
  CRC32             … 中身が同じかの確認（zip の目次にある数字と同じ方式）
  CleanupScanner    … フォルダから「解凍済み」「同じものが2つ」を探す
  ArchiveOperations … 既存。選んだものだけで新しい zip を作る処理を足す（packSelection）

ZipPeek（アプリ）
  CompareView / CompareModel  … 比べる窓
  CleanupView / CleanupModel  … お片付けの窓
  ShareSelection              … 送る（zip を作る → 共有メニュー）
  WindowManager               … 窓を開く入口を足す
  ArchiveView                 … 「その他」と右クリックに項目を足す

ZipPeekSpotlight（新しい部品・C言語）
  GetMetadataForFile.c … 圧縮ファイルの中の名前を検索用の本文（kMDItemTextContent）に入れる
  main.c / Info.plist  … Mac に「zip・7z・tar…はこの部品で読む」と伝える

6. データ構造

enum DiffStatus { added, removed, changed, same, probablySame }
struct DiffRow { path: String; status: DiffStatus; leftSize: Int64?; rightSize: Int64?; isFolder: Bool }
struct DiffSummary { added, removed, changed, same: Int }

// 変わったかの決め方
// 1) 大きさが違う → 変わった
// 2) 両方に CRC（zip・7z の目次にある確認用の数字）がある → 数字で判断
// 3) フォルダ側は、大きさが同じときだけ CRC を計算する
// 4) どちらにも CRC がない形式（tar など） → 大きさと日付が同じなら「たぶん同じ」
// 名前は Mac と Windows の文字の違い（濁点の扱いなど）をそろえ、.DS_Store・__MACOSX は比べない

enum CleanupReason { extracted(folder: URL), duplicate(of: URL) }
struct CleanupItem { url: URL; size: Int64; reason: CleanupReason }
// 解凍済み：横に同じ名前のフォルダがあり、比べて「消えた」「変わった」が 0
// 同じもの：大きさが同じで、SHA-256（ファイルの指紋）も同じ。新しいほうを候補にする

8. 確かめ方（GitHub Actions の Mac で）

  • 比べる・お片付け：中身の処理を Linux と Mac の両方で自動テスト。画面は今の自動操作テストに「比べる窓を開いて、要約の数が合っているか」「お片付けで候補が出るか」を足す
  • 送る：zip ができて共有メニューが出るところまで（AirDrop で実際に送るところは、テスト用の Mac では確かめられない）
  • 検索：mdimport で部品が呼ばれ、中の名前が入るかを見る。そのうえで mdfind で検索して見つかるか（テスト用の Mac で検索の索引が止まっていたら、ここは未確認として報告）

9. 画面デザイン

サンプルの名前はすべて架空です。

② 比べる窓

要約のチップを押すと、その種類だけに絞り込み。「差分を取り出す」は、右側の「増えた」「変わった」ファイルだけを、フォルダ構成のまま取り出します。左右の入れ替えは真ん中の矢印。

③ 選んだものだけ送る

送る zip の名前は「元の名前_選択.zip」。名前の付け方と Mac 専用の隠しファイルを外すかどうかは、今の圧縮の設定に従います。共有メニューは Mac 標準のもの（中身は Mac 側の設定で変わります）。

④ お片付けの窓

確実なものだけ最初からチェックを入れます。フォルダが一部足りないものはチェックなし＋黄色の注意。行をダブルクリックすると Finder で場所を見せます。

① 中まで見つかる検索（Mac の検索画面での見え方）

10. わかっていないこと・あとで確かめること

  • 検索：テスト用の Mac で検索の索引が動いているか（止まっていたら、実際に検索で見つかるところは未確認のまま出します）
  • 検索：中の名前が多すぎる zip（数十万ファイル）でどこまで入れるか → 先頭から一定量（例：1 MB 分の名前）で打ち切る予定
  • 送る：AirDrop で実際に届くところは、テスト用の Mac では試せない
  • 比べる：tar など確認用の数字（CRC）を持たない形式は「たぶん同じ」になる
